# Phase G8 Backup and Restore Proof Design

**Status:** approved project-order design for implementation  
**Base:** sealed G7 `8d31368eaefd50560855b4ef69050760c1134bee`  
**Branch:** `feat/phase-g8-backup-restore`

**LIVE TRADING: DISABLED.**

## 1. Purpose

G8 proves that a Shreks host can lose its active runtime filesystem/process state, restore the durable PAPER truth that matters, and resume from the same validated state without erased memory, duplicate actions, silent accounting drift, lost proof evidence, or weakened operator safety state.

This phase is operational recovery infrastructure. It does not change strategy, scoring, risk thresholds, sizing, slippage, accounting formulas, promotion rules, wallet/signing/submission authority, or live enablement.

## 2. Recovery invariants

A valid G8 recovery must preserve or reconcile, at minimum:

- authoritative operational SQLite state, including observer history, PAPER state, ledger, processed identities, safety evidence, and persisted PAPER checkpoints;
- E11 evaluation evidence;
- the exact immutable fingerprinted PAPER campaign manifest that attributes the restored state;
- G7 operator risk-control state so a halt/kill latch cannot disappear because of restore;
- G6 durable alert queue/state so pending critical notifications are not silently erased.

The restored PAPER runtime must pass the existing sealed preflight before it is considered usable. Normal restart equivalence and existing accounting/checkpoint invariants remain authoritative.

For any future LIVE runtime, local backups are not sufficient evidence of balances/positions. Onchain truth must be reconciled before live money can resume. G8 does not implement live recovery or live trading.

## 3. Required versus reconstructable artifacts

### Required bundle artifacts

Each completed bundle contains exactly these logical roles:

1. `operational_sqlite` — online SQLite backup of the configured operational database.
2. `e11_evidence` — exact byte snapshot of configured E11 evidence.
3. `campaign_manifest` — exact byte snapshot of the immutable campaign manifest.
4. `operator_risk_control` — exact byte snapshot of configured G7 control state when G7 controls are configured.
5. `alert_state` — exact byte snapshot of configured G6 durable alert state when alerts are configured and state exists.

Optional roles must be explicitly registered by a future approved design. G8 does not invent a production research-data path. If later research data becomes non-reconstructable, it must be added to the recovery contract explicitly rather than silently swept into backups.

### Deliberately excluded

- `/etc/shreks/dashboard-password`;
- `/etc/shreks/telegram-bot-token`;
- provider/API secrets;
- private wallet/signing material;
- derived telemetry such as `/var/lib/shreks/telemetry/current.json`;
- release source/binaries already controlled by the sealed release/deployment path;
- SQLite `-wal` / `-shm` files as separate artifacts.

Secrets require a separate host secret-recovery mechanism. The G8 bundle must remain safe to copy as operational state without unexpectedly becoming a credentials archive.

## 4. Bundle format

A completed snapshot is an immutable directory under a configured backup root, for example:

```text
/var/lib/shreks/backups/
  1787752800000-<manifest-prefix>/
    manifest.json
    artifacts/
      operational.sqlite3
      e11.json
      paper-campaign.json
      operator-control.json
      alerts-state.json
```

The exact directory name is generated by G8 and validated before retention/deletion operations.

`manifest.json` is strict canonical UTF-8 JSON with a versioned schema and includes:

- schema version;
- snapshot creation timestamp;
- PAPER run ID and campaign-manifest fingerprint derived from the staged campaign manifest;
- artifact records with exact logical role, safe relative path, SHA-256, byte size, and required/optional status;
- SQLite integrity result/provenance;
- G8 bundle completion marker represented inside the canonical manifest, not by trusting directory naming alone.

No absolute secret path or secret value is recorded.

Artifact relative paths must be normalized, non-empty, non-absolute, traversal-free, duplicate-free, and must not resolve through symlinks during verification/restore.

## 5. SQLite snapshot semantics

The operational SQLite database is captured with Python's standard-library SQLite online backup API into a staging file. G8 never treats a raw copy of the main database plus WAL as a coherent backup.

After capture, the staged SQLite file must pass `PRAGMA quick_check` (and any stricter checks required by tests) before bundle publication.

The source database is opened for read/backup only. G8 does not mutate the authoritative source database.

## 6. Cross-file coherence without service-control authority

The PAPER runtime writes state across SQLite and E11 on cycle boundaries, so independently copied files can straddle a concurrent cycle. G8 must not solve this by gaining `systemctl`/process-control authority.

Snapshot creation therefore uses a bounded capture-and-verify loop:

1. create a private temporary bundle directory under the backup root;
2. online-backup SQLite;
3. copy required non-SQLite artifacts exactly;
4. verify per-artifact hash/size and canonical/strict formats where available;
5. construct an `ObserverPaperCampaignRuntimeConfig` pointed only at the staged database/E11/manifest and staged risk-control state;
6. run the existing sealed PAPER preflight/bootstrap against the staged snapshot without advancing a cycle;
7. if the staged cross-file state is incoherent because a cycle raced the capture, discard the temporary bundle and retry up to a fixed bounded attempt count;
8. publish only a fully verified canonical completed bundle via atomic directory rename.

A failed backup never mutates PAPER state and never stops/restarts services.

## 7. G6 alert state

Alert state is durable operational state because loss can silently erase unsent critical notifications. It is therefore snapshotted when configured/present.

Alert state is not part of PAPER accounting coherence. Its bytes/hash are verified independently. Missing optional alert state at the very beginning of an alert lifecycle does not invalidate PAPER truth, but a configured existing source that becomes unreadable during capture is a backup failure rather than a fabricated empty queue.

## 8. G7 operator risk-control state

When `SHREKS_RISK_CONTROL_STATE_PATH` is configured, operator control state is required in the bundle and must pass the existing strict G7 decoder.

Restore must never silently replace a latched halt/kill with a default-clear state. A missing or corrupt configured risk-control artifact fails restore verification.

## 9. Restore model

Application code restores only to a caller-provided **empty staging directory**. It never overwrites `/var/lib/shreks`, `/etc/shreks`, active SQLite files, or active service state directly.

Restore workflow:

1. strict-decode bundle manifest;
2. reject unknown roles, missing required artifacts, extra manifest keys, unsafe paths, symlinks, duplicate roles/paths, size mismatch, or SHA mismatch;
3. verify backed-up SQLite integrity;
4. copy artifacts into a new private staging directory with safe fixed filenames/permissions;
5. strict-decode G7 control state and other canonical artifacts where supported;
6. run the existing PAPER preflight against staged DB/E11/manifest/control state;
7. produce a restore-verification result containing campaign fingerprint, run ID, restored PAPER state timestamp/checkpoint identity, and verified artifact hashes;
8. leave staged files untouched for operator-controlled host installation.

If staging target exists and is non-empty, restore fails closed.

## 10. Host restore procedure

The deployment runbook—not application code—owns the controlled host sequence:

- choose a verified completed bundle;
- verify/restore it into staging while PAPER remains halted/offline as appropriate;
- stop the core PAPER target using normal root operator procedures before replacing active durable files;
- retain host secrets separately;
- atomically install staged DB/E11/manifest/risk/alert state with documented ownership/modes;
- run the existing PAPER `--preflight` against installed state before starting the campaign;
- verify release provenance and service health;
- preserve/compare the G7 halt/kill state;
- for future live recovery, reconcile onchain balances/positions before live enablement.

The Python G8 runtime has no service-management commands.

## 11. Runtime configuration

G8 uses a small standalone operational namespace for backup mechanics and reuses authoritative existing path configuration instead of creating shadow trading-policy configuration.

Planned G8 keys:

```text
SHREKS_BACKUP_ROOT=/var/lib/shreks/backups
SHREKS_BACKUP_RETENTION_COUNT=168
SHREKS_BACKUP_MAX_CAPTURE_ATTEMPTS=3
```

The backup runtime reuses:

- `SHREKS_PAPER_CAMPAIGN_OBSERVER_DB_PATH`;
- `SHREKS_PAPER_CAMPAIGN_E11_PATH`;
- `SHREKS_PAPER_CAMPAIGN_MANIFEST_PATH`;
- `SHREKS_RISK_CONTROL_STATE_PATH` when configured;
- `SHREKS_ALERTS_STATE_PATH` when configured.

Retention count and capture attempts are bounded positive integers. No backup key can configure strategy, risk, execution, wallet, signing, submission, or live behavior.

## 12. Retention

Default host example retains 168 completed hourly snapshots (seven days), subject to measured disk capacity. Retention is count-based, deterministic, and only deletes validated completed bundle directories under the configured backup root.

Retention must:

- never traverse outside backup root;
- never delete arbitrary directories/files;
- ignore/reject malformed entries rather than guessing they are backups;
- never delete the newest valid completed bundle;
- run only after a new bundle has been fully published.

Temporary/incomplete captures are cleaned only when their names and parent are known to have been created by the current G8 invocation.

## 13. systemd boundary

Add independent `shreks-backup.service` + `shreks-backup.timer`:

- oneshot service, dedicated `shreks` identity;
- starts the sealed Python G8 backup runtime;
- `ProtectSystem=strict`, `NoNewPrivileges=true`, private temp/devices/proc hardening consistent with existing units;
- `/var/lib/shreks` and `/etc/shreks` read-only except `ReadWritePaths=/var/lib/shreks/backups`;
- no network requirement; restrict address families to local/Unix needs and deny IP network access;
- no `PartOf=shreks.target`, no PAPER/dashboard/alert lifecycle dependency;
- timer scheduled hourly, persistent across reboot, bounded/randomized start delay;
- backup failure is observable but cannot stop, restart, resume, halt, or otherwise control PAPER.

## 14. Security boundary

G8 gains filesystem write authority only inside the configured backup root/staging targets it creates for bundle construction or caller-provided offline restore staging.

It gains no:

- wallet/private-key access;
- signing/submission authority;
- strategy/risk-policy mutation;
- promotion authority;
- live-enable route;
- inbound network listener;
- Telegram command path;
- systemd/service-control authority.

Bundle permissions default private (`0700` directories, `0600` files). G8 does not invent homegrown encryption. Operators may place `/var/lib/shreks/backups` on an encrypted host volume and may copy verified bundles to offline/off-host encrypted storage using ordinary host tooling. No paid cloud dependency is required.

## 15. Failure behavior

Any of the following fails the current snapshot/restore closed:

- source missing/unreadable when required;
- SQLite online backup or integrity failure;
- malformed/corrupt E11/manifest/risk state;
- hash/size mismatch;
- bundle path traversal/symlink/unknown-role/duplicate-role;
- cross-file PAPER preflight mismatch;
- restore target not empty/private-creatable;
- retention target that cannot be proven to be a completed G8 bundle.

Failure never fabricates an empty state or silently resets safety/accounting history.

## 16. Proof requirements

Repository proof must demonstrate:

- WAL-safe online SQLite backup captures committed truth and excludes raw WAL/SHM artifacts;
- source files/DB are unchanged by backup;
- strict canonical bundle manifest round-trip;
- corruption/partial/tampered bundles fail verification;
- source symlinks/path traversal cannot escape boundaries;
- staged restore preserves checkpoint/ledger/E11/campaign attribution and passes existing PAPER preflight;
- G7 kill/halt state survives snapshot/restore exactly;
- G6 pending alert state survives exactly;
- telemetry and secrets are absent;
- retention deletes only oldest verified completed bundles;
- systemd backup service is independent, no-network, write-limited, and has no trading/service authority;
- rollback/runbook procedures preserve state and require preflight before resume.

Real-host proof before live money must additionally test an actual backup, destructive sandbox restore, reboot/restart recovery, permissions, disk capacity/retention, off-host copy if used, and future onchain reconciliation.

## 17. Out of scope

- live trading;
- automatic active-state overwrite;
- automatic service stop/start/restart;
- cloud-specific backup APIs;
- paid backup infrastructure;
- secret backup/key management;
- multi-host consensus/distributed snapshotting;
- Kubernetes/Kafka/microservice backup infrastructure;
- research artifact discovery by globbing arbitrary directories.

## 18. Conclusion

G8 is a fail-closed operational recovery layer around already-sealed state. It uses SQLite's online backup, exact file snapshots, hashes, canonical manifests, existing PAPER preflight, staging-only restore, private permissions, and an independent timer. It protects the truth needed to recover without becoming a new execution or lifecycle authority.

**Profitability remains unproven until real PAPER evidence satisfies the sealed proof gates.**
